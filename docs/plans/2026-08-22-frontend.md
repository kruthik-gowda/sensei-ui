# Sensei Review UI — Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the browser UI for sensei-ui — an inbox of reviewable merge requests, a side-by-side diff with findings pinned to their lines, keyboard triage, and a preview tray that shows exactly what will be posted before anything is.

**Architecture:** Three remaining FastAPI endpoints (`/api/mrs`, SSE progress, `/api/setup`) plus a React SPA built by Vite into `src/sensei_ui/static/`, which FastAPI serves. The React layer is deliberately thin — it renders structures the backend already computed and owns no logic that could misplace a comment. Run generation moves to a background thread so the UI can show progress instead of blocking for minutes.

**Tech Stack:** React 18 + TypeScript + Vite, plain CSS (no component library), FastAPI SSE, Vitest + React Testing Library for the few stateful pieces. Python 3.9+, pytest.

**Spec:** `docs/specs/2026-08-22-design.md`

**Prior plan:** `docs/plans/2026-08-22-backend.md` (complete — 75 tests passing)

## Global Constraints

- Python `>=3.9`. Use `typing.Optional` / `typing.List` / `typing.Dict`, never `X | None` or builtin generics.
- Every Python module stays under 500 lines. `app.py` is already 214 — split rather than let it sprawl.
- **Only `src/sensei_ui/engine.py` may import from `sensei.*`.** `setup.py`'s health checks are the one stated exception.
- Server binds `127.0.0.1` only.
- SQLite lives at `~/.sensei-ui/ui.db`. Never write to `~/.sensei/` — that directory belongs to sensei.
- The React bundle is **committed** to `src/sensei_ui/static/` so running the app needs no Node toolchain.
- Python tests use pytest; `monkeypatch` is stock pytest and is allowed. No mocking framework.
- **The React layer stays thin.** Test the reducer and the API client; do not chase coverage on presentational components — the spec puts risky logic in Python deliberately.
- No finding may be posted that a human has not marked `kept`. No UI affordance may bypass that.

## Existing API (built, tested, do not break)

| Method | Path | Returns |
| --- | --- | --- |
| `GET` | `/api/health` | `{sensei, gitlab, claude}`, each `{ok, detail}` |
| `POST` | `/api/runs` | `{run_id, verify_status}` — **synchronous today; Task 2 changes this** |
| `GET` | `/api/runs/{id}` | `{run, findings, files, test_summary}` |
| `PATCH` | `/api/findings/{id}` | `{ok: true}`; accepts `state` ∈ `pending|kept|discarded` and `edited_body` |
| `POST` | `/api/runs/{id}/post` | `{posted, skipped}`; 409 when the MR head has moved |
| `POST` | `/api/runs/{id}/unpost` | `{removed, restored}` |

A `finding` row carries: `id`, `run_id`, `signature`, `file`, `line`, `kind` (`must|nit|test`), `confidence`, `original_body`, `edited_body`, `state`, `verdict` (`confirm|reject`), `verdict_reason`, `discussion_id`, `posted_at`, `last_seen_generation`.

A `files` entry is `{path, rows}` where each row is `{kind: "context"|"add"|"del"|"meta", old_line, new_line, text}`.

```python
"""Candidate merge requests for review.

The union of reviewer-assigned and assignee-assigned merge requests, because
this team uses both fields and a reviewer who only saw one would miss work.
"""
from typing import Dict, List

QUERY_FIELDS = ("reviewer_username", "assignee_username")


def _project_path_from_reference(reference: str) -> str:
    """`g/p!7` -> `g/p`."""
    return reference.split("!")[0]


def list_candidate_mrs(client, group_path: str, username: str) -> List[Dict]:
    group = client.gl.groups.get(group_path)
    by_id = {}

    for field in QUERY_FIELDS:
        kwargs = {field: username, "state": "opened", "scope": "all",
                  "all": True}
        for mr in group.mergerequests.list(**kwargs):
            if mr.id in by_id:
                continue
            by_id[mr.id] = {
                "project_path": _project_path_from_reference(
                    mr.references["full"]
                ),
                "mr_iid": int(mr.iid),
                "mr_url": mr.web_url,
                "title": mr.title,
                "author": mr.author["username"],
                "head_sha": mr.sha,
            }

    return list(by_id.values())
```

frozen page and no way to tell a slow run from a hung one, so the work moves to

- [ ] **Step 3: Implement `runner.py`**

```python
"""Background run execution and progress fan-out.

A review takes minutes. Holding the HTTP request open for that long leaves the
reviewer unable to distinguish a slow run from a hung one, so the work runs on
a thread and progress is streamed.
"""
import queue
import threading
from typing import Dict, Iterator, List

_SENTINEL = object()


class RunProgress:
    """Per-run event buffer that replays history to late subscribers."""

    def __init__(self) -> None:
        self._lock = threading.Lock()
        self._events: List[Dict] = []
        self._subscribers: List["queue.Queue"] = []
        self._closed = False

    def publish(self, event: Dict) -> None:
        with self._lock:
            self._events.append(event)
            subscribers = list(self._subscribers)
        for subscriber in subscribers:
            subscriber.put(event)

    def history(self) -> List[Dict]:
        with self._lock:
            return list(self._events)

    def subscribe(self) -> Iterator[Dict]:
        subscriber: "queue.Queue" = queue.Queue()
        with self._lock:
            backlog = list(self._events)
            closed = self._closed
            if not closed:
                self._subscribers.append(subscriber)

        for event in backlog:
            yield event
        if closed:
            return

        while True:
            item = subscriber.get()
            if item is _SENTINEL:
                return
            yield item

    def close(self) -> None:
        with self._lock:
            self._closed = True
            subscribers = list(self._subscribers)
            self._subscribers = []
        for subscriber in subscribers:
            subscriber.put(_SENTINEL)


PROGRESS: Dict[int, RunProgress] = {}
_PROGRESS_GUARD = threading.Lock()


def progress_for(run_id: int) -> RunProgress:
    with _PROGRESS_GUARD:
        existing = PROGRESS.get(run_id)
        if existing is None:
            existing = RunProgress()
            PROGRESS[run_id] = existing
        return existing
```

findings on a real merge request and 42 confirmed, pre-accepting would make a
single Post click send all 42 — the reviewer having individually judged none of

extra click in front of it. Pre-discarding is safe in the other direction: the
worst case is a real finding sitting deselected and visible, one keystroke from
rescue. Update `docs/specs/2026-08-22-design.md` to match, and say so in your
report.

```python
def _await_run(client, run_id, timeout=5.0):
    """Block until a background run leaves the `running` state."""
    import time

    deadline = time.time() + timeout
    while time.time() < deadline:
        run = client.get("/api/runs/%d" % run_id).json()["run"]
        if run["status"] != "running":
```

```python
def save_gitlab_config(gitlab_url: str, gitlab_pat: str, username: str) -> Dict:
    """Write GitLab credentials to sensei's config, then re-check health.

    Merges into the existing file rather than replacing it — sensei owns other
    keys there (batch_size, ai_cli, model) and clobbering them would silently
    reconfigure the CLI.
    """
    if not gitlab_pat or not gitlab_pat.strip():
        raise ValueError("gitlab_pat must not be empty")

    existing = {}
    if os.path.exists(CONFIG_PATH):
        with open(CONFIG_PATH) as fh:
            existing = yaml.safe_load(fh) or {}

    existing.update({
        "gitlab_url": gitlab_url,
        "gitlab_pat": gitlab_pat.strip(),
        "username": username,
    })

    directory = os.path.dirname(CONFIG_PATH)
    if directory:
        os.makedirs(directory, exist_ok=True)

    with open(CONFIG_PATH, "w") as fh:
        yaml.safe_dump(existing, fh)
    os.chmod(CONFIG_PATH, 0o600)

    return health()
```

```typescript
import type {
  Finding, Health, MrSummary, ProgressEvent, RunDetail,
} from "./types";

export class ApiError extends Error {
  status: number;
  constructor(status: number, message: string) {
    super(message);
    this.status = status;
  }
}

async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const response = await fetch(path, {
    headers: { "Content-Type": "application/json" },
    ...init,
  });
  const body = await response.json().catch(() => ({}));
  if (!response.ok) {
    throw new ApiError(response.status, body?.detail ?? response.statusText);
  }
  return body as T;
}

export const getHealth = () => request<Health>("/api/health");

export const getMrs = async (): Promise<MrSummary[]> =>
  (await request<{ mrs: MrSummary[] }>("/api/mrs")).mrs;

export const startRun = (mrUrl: string) =>
  request<{ run_id: number }>("/api/runs", {
    method: "POST",
    body: JSON.stringify({ mr_url: mrUrl }),
  });

export const getRun = (runId: number) =>
  request<RunDetail>(`/api/runs/${runId}`);

export const patchFinding = (
  findingId: number,
  patch: Partial<Pick<Finding, "state" | "edited_body">>
) =>
  request<{ ok: boolean }>(`/api/findings/${findingId}`, {
    method: "PATCH",
    body: JSON.stringify(patch),
  });

export const postRun = (runId: number) =>
  request<{ posted: number; skipped: number }>(`/api/runs/${runId}/post`, {
    method: "POST",
  });

export const unpostRun = (runId: number) =>
  request<{ removed: number; restored: number }>(
    `/api/runs/${runId}/unpost`,
    { method: "POST" }
  );

export function subscribeToRun(
  runId: number,
  onEvent: (event: ProgressEvent) => void
): () => void {
  const source = new EventSource(`/api/runs/${runId}/events`);
  source.onmessage = (message) => {
    const event = JSON.parse(message.data) as ProgressEvent;
    onEvent(event);
    if (event.stage === "done" || event.stage === "failed") source.close();
  };
  source.onerror = () => source.close();
  return () => source.close();
}
```

```tsx
import { useCallback, useEffect, useState } from "react";
import { getRun, patchFinding } from "./api";
import DiffView from "./DiffView";
import FindingCard from "./FindingCard";
import PostTray from "./PostTray";
import type { Finding, RunDetail } from "./types";

export default function Review({
  runId,
  onBack,
}: {
  runId: number;
  onBack: () => void;
}) {
  const [detail, setDetail] = useState<RunDetail | null>(null);
  const [selectedId, setSelectedId] = useState<number | null>(null);
  const [error, setError] = useState<string | null>(null);

  const load = useCallback(() => {
    getRun(runId).then(setDetail).catch((e) => setError(String(e.message)));
  }, [runId]);

  useEffect(load, [load]);

  const change = useCallback(
    async (finding: Finding, patch: Partial<Finding>) => {
      setDetail((current) =>
        current
          ? {
              ...current,
              findings: current.findings.map((f) =>
                f.id === finding.id ? { ...f, ...patch } : f
              ),
            }
          : current
      );
      try {
        await patchFinding(finding.id, patch);
      } catch (e) {
        setError(String((e as Error).message));
        load();
      }
    },
    [load]
  );

  if (error) return <p className="error">{error}</p>;
  if (!detail) return <p className="muted">Loading review…</p>;

  const { run, findings, files } = detail;
  const offDiff = findings.filter((f) => f.line === null);
  const triaged = findings.filter((f) => f.state !== "pending").length;

  return (
    <>
      <div className="row header">
        <button onClick={onBack}>← Inbox</button>
        <h1>
          !{run.mr_iid} <span className="muted">{run.project_path}</span>
        </h1>
        <span className="grow" />
        <span className="muted">
          {triaged} of {findings.length} triaged · reviewed at{" "}
          {run.head_sha.slice(0, 8)}

          <h3 className="filepath">Not anchored to a diff line</h3>

            <FindingCard
              key={finding.id}
              finding={finding}
              isSelected={selectedId === finding.id}
              onChange={(patch) => change(finding, patch)}
            />
          ))}
        </section>
      )}

      {files.map((file) => (
        <DiffView
          key={file.path}
          file={file}
          findings={findings.filter((f) => f.file === file.path)}

          onSelect={setSelectedId}
```

```typescript
import type { Finding } from "./types";

export interface PostPlan {
  inline: Finding[];
  summary: Finding[];
  posted: Finding[];
}

/**
 * Display-only mirror of the backend's plan_posts rule.
 *
 * The backend decides what is actually posted. This exists so the reviewer
 * sees placement — especially the demotion of an unanchored must-fix to the
 * summary — before anything is sent.
 */
export function planPreview(findings: Finding[]): PostPlan {
  const plan: PostPlan = { inline: [], summary: [], posted: [] };

  for (const finding of findings) {
    if (finding.state === "posted") {
      plan.posted.push(finding);
      continue;
    }
    if (finding.state !== "kept") continue;

    if (finding.kind === "must" && finding.line !== null) {
      plan.inline.push(finding);
    } else {
      plan.summary.push(finding);
    }
  }

  return plan;
}
```

```tsx
import { useState } from "react";
import { ApiError, postRun, unpostRun } from "./api";
import { planPreview } from "./plan";
import type { Finding } from "./types";

export default function PostTray({
  runId,
  findings,
  onDone,
}: {
  runId: number;
  findings: Finding[];
  onDone: () => void;
}) {
  const [confirming, setConfirming] = useState(false);
  const [busy, setBusy] = useState(false);
  const [message, setMessage] = useState<string | null>(null);
  const [stale, setStale] = useState(false);

  const plan = planPreview(findings);
  const total = plan.inline.length + plan.summary.length;

  const send = async () => {
    setBusy(true);
    setMessage(null);
    try {
      const result = await postRun(runId);
      setMessage(`Posted ${result.posted}, skipped ${result.skipped}.`);
      setConfirming(false);
      onDone();
    } catch (e) {
      if (e instanceof ApiError && e.status === 409) {
        setStale(true);
        setMessage(e.message);
      } else {
        setMessage(String((e as Error).message));
      }
    } finally {
      setBusy(false);
    }
  };

  const undo = async () => {
    setBusy(true);
    try {
      const result = await unpostRun(runId);
      setMessage(`Removed ${result.removed} comment(s).`);
      onDone();
    } finally {
      setBusy(false);
    }
  };

  return (
    <aside className="tray">
      <div className="row">
        <strong>{total} to post</strong>
        <span className="muted">
          {plan.inline.length} inline · {plan.summary.length} in summary
        </span>
        <span className="grow" />
        {plan.posted.length > 0 && (
          <button onClick={undo} disabled={busy}>
            Undo {plan.posted.length} posted
          </button>
        )}
        <button
          onClick={() => setConfirming(true)}
          disabled={busy || stale || total === 0}
        >
          Post…
        </button>
      </div>

      {stale && (
        <p className="error">
          This review is stale — the merge request has new commits. Re-review
          before posting.
        </p>
      )}

      {message && !stale && <p className="muted">{message}</p>}

      {confirming && (
        <div className="preview">
          <h4>Inline threads ({plan.inline.length})</h4>
          {plan.inline.map((f) => (
            <div key={f.id} className="preview-item">
              <code>
                {f.file}:{f.line}
              </code>
              <pre>{f.edited_body ?? f.original_body}</pre>
            </div>
          ))}

          <h4>Summary comment ({plan.summary.length})</h4>
          {plan.summary.map((f) => (
            <div key={f.id} className="preview-item">
              <code>
                {f.file}
                {f.line === null ? " (not on the diff)" : `:${f.line}`}
              </code>
              <pre>{f.edited_body ?? f.original_body}</pre>
            </div>
          ))}

          <div className="row">
            <button onClick={send} disabled={busy}>
              {busy ? "Posting…" : `Post ${total} to GitLab`}
            </button>
            <button onClick={() => setConfirming(false)}>Cancel</button>
          </div>
        </div>
      )}
    </aside>
  );
}
```

```typescript
  it("stops at the end rather than wrapping", () => {
    expect(nextSelection([f(1), f(2)], 2, 1)).toBe(2);

  it("stops at the start rather than wrapping", () => {
    expect(nextSelection([f(1), f(2)], 1, -1)).toBe(1);
  });

  it("returns null for an empty list", () => {
    expect(nextSelection([], null, 1)).toBeNull();

});
```

```typescript
import { useEffect } from "react";
import type { Finding } from "./types";

export function nextSelection(
  findings: Finding[],
  currentId: number | null,
  direction: 1 | -1
): number | null {
  if (findings.length === 0) return null;
  if (currentId === null) return findings[0].id;

  const index = findings.findIndex((f) => f.id === currentId);
  if (index === -1) return findings[0].id;

  const next = index + direction;
  if (next < 0 || next >= findings.length) return currentId;
  return findings[next].id;
}

const EDITABLE = new Set(["INPUT", "TEXTAREA"]);

export function useTriage({
  findings,
  selectedId,
  onSelect,
  onChange,
  onHelp,
}: {
  findings: Finding[];
  selectedId: number | null;
  onSelect: (id: number | null) => void;
  onChange: (finding: Finding, patch: Partial<Finding>) => void;
  onHelp: () => void;
}) {
  useEffect(() => {
    const handler = (event: KeyboardEvent) => {
      const target = event.target as HTMLElement | null;
      if (target && EDITABLE.has(target.tagName)) return;
      if (event.metaKey || event.ctrlKey || event.altKey) return;

      const selected = findings.find((f) => f.id === selectedId) ?? null;

      switch (event.key) {
        case "j":
          onSelect(nextSelection(findings, selectedId, 1));
          break;
        case "k":
          onSelect(nextSelection(findings, selectedId, -1));
          break;
        case "a":
          if (selected) {
            onChange(selected, { state: "kept" });
            onSelect(nextSelection(findings, selectedId, 1));
          }
          break;
        case "d":
          if (selected) {
            onChange(selected, { state: "discarded" });
            onSelect(nextSelection(findings, selectedId, 1));
          }
          break;
        case "e":
          if (selected) {
            const node = document.querySelector<HTMLElement>(
              `[data-finding-id="${selected.id}"] .body`
            );
            node?.dispatchEvent(
              new MouseEvent("dblclick", { bubbles: true })
            );
            event.preventDefault();
          }
          break;
        case "?":
          onHelp();
          break;
        default:
          return;
      }
    };

    window.addEventListener("keydown", handler);
    return () => window.removeEventListener("keydown", handler);
  }, [findings, selectedId, onSelect, onChange, onHelp]);
}
```

The `EDITABLE` guard matters: without it, typing the letter `d` into a comment
you are editing would discard the finding instead.

```tsx
import { useState } from "react";
import type { Health } from "./types";

export default function Setup({
  health,
  onDone,
}: {
  health: Health;
  onDone: () => void;
}) {
  const [url, setUrl] = useState("https://gitlab.com");
  const [pat, setPat] = useState("");
  const [username, setUsername] = useState("");
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const save = async () => {
    setBusy(true);
    setError(null);
    try {
      const response = await fetch("/api/setup", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ gitlab_url: url, gitlab_pat: pat, username }),
      });
      const body = await response.json();
      if (!response.ok) throw new Error(body.detail ?? "Setup failed");
      if (!body.gitlab?.ok) throw new Error(body.gitlab?.detail ?? "GitLab rejected the token");
      onDone();
    } catch (e) {
      setError(String((e as Error).message));
    } finally {
      setBusy(false);
    }
  };

  return (
    <section className="setup">
      <h1>Setup</h1>

      <ul className="checks">
        {(["sensei", "gitlab", "claude", "style_profile"] as const).map((key) => (
          <li key={key} className={health[key].ok ? "ok" : "bad"}>
            <strong>{key}</strong> — {health[key].detail}
            {key === "claude" && !health[key].ok && (
              <div className="muted">
                Run <code>claude /login</code> in a terminal, then reload.
              </div>
            )}
          </li>
        ))}
      </ul>

      {!health.gitlab.ok && (
        <div className="form">
          <label>
            GitLab URL
            <input value={url} onChange={(e) => setUrl(e.target.value)} />
          </label>
          <label>
            Personal access token (<code>api</code> scope)
            <input
              type="password"
              value={pat}
              onChange={(e) => setPat(e.target.value)}
              autoComplete="off"
            />
          </label>
          <label>
            Your GitLab username
            <input
              value={username}
              onChange={(e) => setUsername(e.target.value)}
            />
          </label>
          <button onClick={save} disabled={busy || !pat || !username}>
            {busy ? "Verifying…" : "Save and verify"}
          </button>
          {error && <p className="error">{error}</p>}
        </div>
      )}
    </section>
  );
}
```

```tsx
export default function App() {
  const [runId, setRunId] = useState<number | null>(runIdFromPath());

    getHealth().then(setHealth).catch(() => setHealth(null));

  const ready = health.sensei.ok && health.gitlab.ok && health.claude.ok;
  if (!ready) {

      ) : (
        <Review runId={runId} onBack={openInbox} />
```

```markdown
# sensei-ui

Triage automated code-review findings before they reach a colleague's merge
request.

[sensei](https://github.com/pulkit004/sensei) generates review findings; this
puts a browser in front of them so you decide what gets posted. Claude
adjudicates each finding against the diff first, marking the ones it cannot
substantiate — but it annotates, never drops, and nothing reaches GitLab that
you have not kept.

## Install

    pip install sensei-review sensei-ui
    sensei-ui

The first run opens a setup wizard: paste a GitLab token, and it verifies the
token and your Claude CLI login before letting you review anything.

## Using it

1. **Inbox** — open merge requests where you are reviewer or assignee. A
   `stale` badge means the branch moved since you last reviewed it.
2. **Review** — findings pinned to their diff lines. `j`/`k` move, `a` keeps,
   `d` discards, `e` edits, `?` shows the keys.
3. **Post** — the preview shows exactly what lands where, including findings
   demoted to the summary because their line is not on the diff. Posting is
   blocked outright if the branch moved since the review.
4. **Undo** — removes the threads a run created.
```

## Out of scope for this plan

- Hosted multi-user mode — the spec rules it out; local-first is the design
- Real-time collaboration between two reviewers on one merge request
- Syntax highlighting in the diff — plain monospace is legible and adding a
  highlighter means shipping a grammar bundle for every language in the repo
- Virtualised rendering of very large diffs. A 27-file review renders fine; if
